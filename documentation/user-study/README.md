# Проверка MedPredict с пользователями — комплект ведущего

Сессии не проводились. До первой сессии зафиксируйте в журнале раунда хэш [протокола](../12_Проверка_с_пользователями_протокол.md) и версию приложения. Оценщики и ведущие используют одну и ту же версию материалов.

## Перед сессией

1. Пригласите 8–12 совершеннолетних студентов вне команды. Определите язык участника и выдайте следующий уникальный код `P01`, `P02` и т. д.
2. Подготовьте [согласие RU/KK](consent.md), [карточки A/B/C](cards.md), [скрипт ведущего](moderator.md) и [лист наблюдения](observation.md). Выдавайте только блок на языке участника, без сверки для ведущего. C2 храните отдельно до появления оценки C1.
3. Подготовьте [SUS](sus.md) и [семь вопросов](comprehension.md). Выдавайте только формы участника, без ключа, сначала SUS.
4. В новом профиле или приватном окне откройте главную страницу. После сессии закройте окно и удалите синтетический PDF. Вводите только данные из карточек.

### Запуск закреплённой сборки

Нужны Java 17+, Node.js 22.12+ и npm. Из корня основной копии создайте отдельный worktree.

```sh
git worktree add --detach ../MedPredict-study 168ff1949cfbd741e185b468164feb64a2f22843
```

В первом терминале из корня основной копии укажите путь к существующему закрытому файлу настроек Gemini. Ключ хранится только на машине ведущего. Зафиксированный режим требует `gemini-3.5-flash-lite`.

```sh
study_env="$PWD/backend/.env"
cd ../MedPredict-study/backend
MAVEN_OPTS=-Djava.net.preferIPv4Stack=true \
PORT=8081 CORS_ALLOWED_ORIGINS=http://127.0.0.1:5175 \
MEDPREDICT_MODEL_DIRECTORY="$PWD/../ml-ai/artifacts" \
MEDPREDICT_MODEL_VERSION=MedPredict-SBP-mlp-v2 \
MEDPREDICT_ENV_FILE="$study_env" GEMINI_MODELS=gemini-3.5-flash-lite \
sh ./mvnw spring-boot:run -Dspring-boot.run.profiles=onnx
```

Во втором терминале из корня основной копии запустите frontend.

```sh
cd ../MedPredict-study/frontend
npm ci
VITE_API_MODE=real VITE_API_BASE_URL= API_PROXY_TARGET=http://127.0.0.1:8081 \
npm run dev -- --port 5175 --strictPort
```

Откройте [локальную главную](http://127.0.0.1:5175). `/api/v1/health/ready` должен вернуть `ready: true`, `modelVersion: MedPredict-SBP-mlp-v2`, `demo: false`. `/api/v1/assistant/status` должен вернуть `available: true` с базой `kb-2026-11-22`. До первого участника сверяйте A/B/C, предупреждение B, единицы глюкозы и объяснение B в ассистенте, скачивание и открытие PDF B. Карточки, интерфейс RU/KK, обе отправки в ассистент и скачивание PDF уже проверены на этом коммите. Синтетический показанный результат C и вымышленное показание тонометра показываются раздельно. [Ожидаемые результаты карточек](cards.md#сверка-для-ведущего--жүргізушіге-арналған-тексеру)

### CSV и разметка

Скопируйте [пустой шаблон](responses-template.csv) в закрытый локальный каталог. Путь `.private/` игнорируется Git.

```sh
mkdir -p documentation/user-study/.private
cp documentation/user-study/responses-template.csv documentation/user-study/.private/responses.csv
```

Используйте CSV UTF-8 с запятыми в качестве разделителей. Сохраните заголовок и все столбцы. У каждого согласившегося участника одна строка, уникальный `participant_id`, `round` 1 или 2 и `language` `ru` или `kk`. Пропуски оставляйте пустыми, ноль времени или ошибок используйте только для фактически измеренного нуля.

| Поля | Что внести |
|---|---|
| `t1`–`t6` с суффиксами `_seconds`, `_errors`, `_status` | Секунды, целое число ошибок и код статуса из листа наблюдения |
| `sus1`–`sus10` | Первичные ответы 1–5 |
| `q1`, `q3`, `q4`, `q6`, `q7` | `yes`, `no`, `unsure` |
| `q2_text`, `q5_text` | Первый ответ без личных данных словами участника |
| `q2` и `q5` с суффиксами `_rater1`, `_rater2`, `_final` | `correct`, `partial`, `incorrect` |

Два оценщика независимо заполняют свои колонки по [рубрике](comprehension.md#ключ-для-команды--топқа-арналған-жауап-кілті). При совпадении исходных оценок `_final` можно оставить пустым. При расхождении сохраните обе оценки, запишите причину в локальном листе наблюдения и внесите согласованную оценку в `_final`. Причины и комментарии публикуются только обезличенными темами. Не коммитьте CSV, согласия, заметки или записи сессий.

### Анализ и отчёт

Запустите из корня основной копии после сессий и сверки оценщиков. Нужен Python 3 без дополнительных пакетов.

```sh
python3 documentation/user-study/analyze.py documentation/user-study/.private/responses.csv
```

Вывод JSON содержит только агрегаты первого и второго раундов. `met` — выполнен порог, `not_met` — не выполнен, `provisional` — пока нет данных для окончательной отметки, `descriptive` — результат перепроверки. Ключ `estimate_meets_threshold` показывает точечное сравнение с порогом даже при предварительном статусе. `null` означает, что метрика не определена. Результаты внесите в [шаблон итогового отчёта](../12_Проверка_с_пользователями.md). [Синтетический тестовый CSV](tests/responses-synthetic.csv) служит для проверки скрипта.
