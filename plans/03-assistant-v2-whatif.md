# План 3. Ассистент A-v2 и режим «что если»

## Часть A — ассистент A-v2 (если A-v1.1 не прошёл пороги или руководитель дала замечания)
1. Разобрать провалы из `assistant/eval/review-A-v1.1.md`: нет нужного факта в базе, плохой казахский, ложный отказ.
2. Дополнить базу знаний (только факты из документации, у каждого — источник) и уточнить промпт.
3. Расширить набор вопросов: +20 новых, которые не видела ни одна версия (часть — от пользователей из плана 1).
4. Зарегистрировать A-v2 → полный прогон на старых и новых вопросах → сравнить с A-v1.1.
5. Опционально: проверка качества ответа вторым LLM («судья») плюс ручная выборка.

## Часть B — режим «что если»
**Идея:** на экране результата выбрать один показатель (например, ИМТ) и подвинуть ползунок; оценка пересчитывается.
- Backend: без изменений, используется тот же `POST /api/v1/predictions`; запросы с задержкой (debounce) 300 мс и отменой устаревших.
- Frontend: компонент `WhatIfPanel` — ползунок в пределах границ поля из метаданных, исходная и новая оценка, разница.
- Обязательная подпись: «Это поведение модели, а не прогноз эффекта лечения».
- Тесты: отмена устаревших запросов, границы ползунка, локализация.
